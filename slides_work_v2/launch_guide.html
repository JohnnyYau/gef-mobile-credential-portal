Launching the portal

From a cold laptop to a booth that is safe to open — one command, then three checks that tell you the truth. Nothing on this page changes the credential data.

0One-time prerequisites

The folder …\GEF-mobile-project\verification-portal — everything below runs from inside it
Python .venv\Scripts\python.exe (3.13). If this is missing, nothing else will work.
Tunnel binary %LOCALAPPDATA%\cloudflared\cloudflared.exe — the launcher uses this copy; a second one sits in C:\Program Files (x86)\cloudflared\.
The chain data\demo-chain\ — 5 block files, info.yaml listing 2 signers, keys\

1Launch — double-click, or one line

Easiest: open the folder and double-click start_showcase.bat. From a PowerShell window instead:

# from verification-portal\ .\start_showcase.ps1 # add -NoBrowser to skip opening the stage screen

It does six things, in the only order that works — each one is something that normally kills a demo:

Step 2 retries by itself: Cloudflare rate-limits quick tunnels, so the script waits and asks again up to six times. If it gives up, it says so — rerun a few minutes later.

What it prints when it worked:

PUBLIC https://something.trycloudflare.com LOCAL http://127.0.0.1:8013/showtime?token=demo-staff-token QR on the stage points at the PUBLIC address. assistant warmed (first chat is normally ~30 s)

It writes that address into showcase-url.txt and opens the stage screen for you. The public address changes on every launch — that file is the source of truth, not this page.

3Launching without a tunnel

Hostile Wi-Fi: skip Cloudflare. Visitors then look at your screen and the QR is decoration — say so, rather than letting someone scan a dead link.

# verification-portal\ , one PowerShell window $env:ADMIN_TOKEN="demo-staff-token"; $env:ISSUER_TOKEN="demo-issuer-token" $env:CAPABILITY_SECRET="showcase-capability-secret-2026"; $env:PUBLIC_MODE="0"; $env:DEMO_OPEN="1" $env:TRUSTED_PROXIES="127.0.0.1" # no PUBLIC_BASE_URL: links stay on 127.0.0.1 .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8013 --no-proxy-headers

4Stopping, restarting, and the lid

  • Stop: Ctrl-C in the server window, close cloudflared. The launcher kills both next time anyway.
  • Restart mid-day: run the launcher again — it frees 8013, gets a new public URL, and the stage QR follows, because the server reads PUBLIC_BASE_URL at boot.
  • Closing the lid kills the tunnel. Power plan “never sleep”, laptop plugged in — the most common way this demo dies.

Flags: -NoBrowser (server + tunnel, no browser)  ·  -Port 8014 (only if 8013 is taken — then every printed URL needs the new port)  ·  -AdminToken … (only if changed deliberately).

6Not while people are watching

four ways to lose the booth
  • Run the launcher on stage — it kills 8013 and the tunnel, and mints an unprinted URL.
  • Set PUBLIC_MODE=1: issuing and revoking are off, so there is nothing to show.
  • Delete or “tidy” data\ — every hash you have quoted lives there.
  • Issue with a real person’s name or student ID — append-only means it stays forever.
