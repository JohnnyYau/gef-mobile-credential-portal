開攤，與台上那四分鐘

Mobile Credential Verification Portal — 一張證書，四個環節 · 2026 年 11 月

開場前十分鐘

  1. 跑 scripts\preflight.py，要看到 11/11。紅色那一行就是唯一要做的事。
  2. 隧道若已經死：start_showcase.ps1 -NoBrowser。它會換一個新網址，preflight 會自己重驗。
  3. 用手機掃舞台上那枚 QR，要落在 /verify?hash=…，並看到「真實有效」。
  4. 投影機接上後，把瀏覽器縮放調到 100%，全螢幕 F11。
  5. 電源計畫設成永不睡眠，機器不要合蓋——合蓋那一下，隧道就跟著死。

台上 90 秒版

0:00海報那句話：一張證書，四個環節。問題是「驗一張文憑要打幾通電話」。
0:10開舞台頁（下面那條網址），讓它自己跑：簽發 → 驗證 → 註銷 → 再驗。
0:45指著四張收據：這些毫秒是真的量出來的，不是動畫。
1:10收在一句話：鏈上只有雜湊與簽名，0 筆姓名與成績。

台上 4 分鐘版

  1. / 貼上 demo 憑證 → 一句結論 + 四行過程（第 1 塊，11 月 20 日簽發）。
  2. 再貼已註銷那條 → 「已註銷」，原因寫在鏈上（當初簽發有誤）。
  3. /issue 填三格 → 簽發 → 它會告訴你現在是第幾塊。
  4. /showtime 走完四環節，讓收據自己填滿。
  5. 簡報第 6 頁：三條原則 + 四個數字，收尾。

這兩個網址，先存進書籤

  • 舞台頁：127.0.0.1:8013/showtime
  • 要它自己跑完，後面接：?auto=1&token=demo-staff-token
  • 驗證：127.0.0.1:8013/　簽發：127.0.0.1:8013/issue

壞了怎麼辦

隧道掛了改用 http://127.0.0.1:8013 直接展示；QR 改口頭說「結束後掃海報」。
整台機器掛了播 demo-media\GEF-mobile-walkthrough.mp4（68 秒，有字幕，不需要聲音）。
只有 22 秒播 GEF-mobile-stage-run.mp4，旁白由你自己講。
投影很暗用 /showtime：深底白字，就是為投影做的。
評審要親手驗遞手機打 /verify，或掃海報的 GitHub 碼自己起一份。

四件不要做

  • 不要清 verification-portal\data\：四個樣本、文件裡的指紋、海報與影片裡的塊號全部作廢。
  • 不要在台上跑 start_showcase：它會殺掉 8013 與隧道，當場換一個沒人知道的網址。
  • 不要簽發真實學生資料：上鏈不可刪，名字與學號會留在示範鏈上。
  • 不要說「區塊鏈保證是真的」：我們只保證「這一刻、這六項檢查通過」。這是我們自己寫在收據裡的話。

三個數字，張口就來

六項鏈完整、簽名方受信、鏈上有紀錄、雜湊相符、簽名有效、未被撤銷。
兩種後量子ML-DSA-65 與 RSA-PSS-2048 並存，簽名方可以輪替。
0上鏈的姓名與成績。只有雜湊與簽名。
一句話版本：「一張文憑，四個環節都寫在鏈上——你可以看著它跑完，也可以自己掃碼再跑一次。」
