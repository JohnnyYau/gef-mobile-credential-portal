## 1. 关键前置：块哈希覆盖整块，所以只能加字段

`append_block` 的链式哈希是：

```python
prev_hash_sum = crypto_util.hash_json(prev_block, content_hash_algo)
```

即**对整块 dict 做 JCS + sha3_512**，包含 `DataSignatureInfo`。

这决定了两件事：

1. 往新块里加字段，只改变该块自身的哈希与**后续**块的 `prevHashSum`——旧块里一个字节都没动；
2. **绝不能对旧块补字段**。补了就等于改了它的哈希，它自己和它的后继块全部 `prevHashSum` 断裂，整个链变成"数据损坏"。

所以本步的形态是：**新块写全字段，旧块保持原样，验签两边都认**。

### 2.1 签名记录字段对照

| 计划要求 | 字段 | 旧块 | 新块 |
|---|---|---|---|
| 算法标识 | `DSAlgo` | 有 | 有 |
| 签发方指纹 | `DSsha256fgpt`（+`DSsha1fgpt`） | 有 | 有 |
| nonce | `DSnonce` | 有 | 有 |
| **被签名消息摘要** | `DSmessageDigest` | **无** | **有** |
| 签名值 | `DSignature` | 有 | 有 |
| **签名方案版本** | `DSscheme` = `hmac-nonce-wrap-v1` | **无（隐式 v1）** | **有** |

`DSver` 保持 `1` 不动——它原来是"记录版本"，不是"签名方案版本"。用一个新字段明确表达方案，比把 `DSver` 从 1 改成 2、再让代码去猜"1 是老格式还是老方案"干净得多。

### 2.2 验签的三条新规则

```
DSscheme 存在且 != "hmac-nonce-wrap-v1"  → 失败（不认识就绝不放行）
DSmessageDigest 存在 且 != 重算值        → 失败
两者都不存在（旧块）                      → 照旧验签，不额外要求
```

第 1 条是这次最有安全意义的补充：**未知方案视为失败**。若将来引入 v2，旧验证器不会因为"不认识所以跳过"而被动接受一个新格式的块。这类"fail closed"必须显式写，默认行为不会自动具备。

第 2 条让"记录里说的和实际签的不一致"成为独立可查的失败，不依赖签名算法是否恰好报错。

### 2.3 单一来源

签名与验签此前各自算一遍被签消息（`sign_json` 里 `_hmac_b64(...)`、`verify_ds` 里同样的表达式）。现在都走 `signature_message()`：

- 两边不可能在"消息是什么"上漂移；
- `DSmessageDigest` 的写入也用它，三处一致。

**没有**把 nonce-HMAC 包裹换成标准 detached signature。计划里那一条写的是"**评估**"，且明确要求过渡期双格式。这一步只做"记录显式化"，算法不变——换算法是链语义变更，需要 v2 方案与全链重签决策，不在本步。

## 4. 过程中我制造并修掉的一个语法错误（如实记录）

给 `sign_json` 做"删掉多余空行"这类无害编辑时，Edit 的 old/new 差异把 `elif` 拼到了上一行：

```python
signature = private_key.sign(message)    elif isinstance(private_key, rsa.RSAPrivateKey):
```

这是**语法错误**，会让整个 `crypto_util` 导入失败——这不是"测试没抓到的隐患"，是编辑器层面我自己的失误。当场读到文件确认并修正。

**教训**：想删空行时不该用 Edit 做"只差一个换行"的替换。这种替换最容易吃掉或并进换行，而它在 diff 里看起来"只少了一行"。

## 5. 遗留与明确未做

1. **nonce-HMAC 包裹未替换为标准 detached signature**：计划原文是"评估替换"，且要求过渡期双格式可验。要做就得引入 v2 方案 + 新块写 v2 + 旧块按 v1 验，是一次独立的链语义变更。本步只把"记录说了什么"显式化。
2. **`DSsha1fgpt` 仍在写**：SHA-1 指纹只作兼容字段保留，不参与任何判定（判定用 `DSsha256fgpt`）。移除会破坏旧块比对面，不建议做。
3. **`rawjsondocs` 明文索引仍未迁库**（U2 遗留延续）。
4. **本步没有新增正式测试模块**：验证靠一次性冒烟脚本（第 3.1 节 9 项）。要固化成回归，应并入 `tests/test_property_crypto.py` 或新建 `test_chain_schema.py`——后者会让模块数再 +1，留待与 U4.3 的"损坏注入用例"一起做，避免连开两个模块。
