## 2. 隐私为什么必须变成策略对象

改造前的规则是**正确的**，但它是「恰好正确」：

```python
pp = d.get("PersonalParticulars", {})
sid = str(pp.get("StudentID", ""))
masked = (sid[:4] + "****") if len(sid) == 8 else ("****" if sid else "")
```

「DOB 永不入档」之所以成立，不是因为有东西在拦，而是因为**没人往字典里写**。任何人为了让前端多显示一个字段而加一行 `"dob": pp.get("DOB")`，测试仍然会绿——除非那条测试正好查这个人的档案。这类规则在代码评审里看不见，在 diff 里也只是一行新增。

现在规则是数据：

```python
PROFILE_WHITELIST = {
  "PersonalParticulars": ("Surname", "GivenNames", "StudentID"),
  "AcademicInfo":       ("DegreeName", "DegreeStartDate", "DegreeEndDate", "Honour"),
  "DocumentInfo":       ("DocType", "IssuingO", "IssuingOU", "DateOfIssue"),
}
NEVER_DISCLOSE = {DOB, DateOfBirth, BirthDate, Sex, Gender, Nationality,
                  Email, Phone, Mobile, Address, IDCardNo, PassportNo, HKID, …}
```

`_profile()` 现在只做一件事：从三个 section 里各 `PRIVACY.build(section, raw)` 一次，其余字段根本到不了 profile。

**白名单与黑名单都查，顺序是白名单先、黑名单后**。有一条测试专门验证这个顺序：即使有人误把 `DOB` 写进 whitelist，`build()` 仍会拒绝——因为拒绝发生在白名单筛选之后，是独立的一道闸。

### 2.1 `violations()` 是断言，不是过滤器

它递归扫描整个结构，返回所有飘出来的禁字段路径，`assert_clean()` 打到 `logger.error`。`_profile()` 末尾调用一次，label 带哈希前缀，便于从日志反查到具体是哪份凭证。

刻意**不做自动清洗**：清洗会把「有人试图泄露」变成「悄悄没泄露」，问题就永远没人修。当前行为是「按构造不可能违规 + 一旦违规立刻在日志里叫」。

## 3. 会话存储接口

改造前 `_sessions` 是模块级 dict：进程内、上限 200 硬编码在解析器里、换后端只能改代码。

现在：

```python
class InMemorySessionStore:      # get / set / clear / __contains__ / __len__
    def __init__(self, limit=None): ...
def open_session_store(backend=None): ...
```

- 默认 `memory`，LRU 用 `OrderedDict.move_to_end` 实现——**这与旧实现不同**：旧的是 FIFO（`pop(next(iter(...)))`），会把刚刚活跃的会话踢掉；现在是真正的 LRU。
- 上限来自 `config.SESSION_LIMIT`（env 不可覆盖，属运营常量，与 U1.4 一致）。
- `SESSION_BACKEND=redis` **不假装能用**：返回内存实现并 `logger.warning` 说明「会话不会跨 worker 共享」。留 `TODO[external-redis]` 占位，写明真正实现需要连接池 / key 命名空间 / 序列化契约，且 `SESSION_LIMIT` 要映射成 TTL 而不是 LRU 上限。

旧的 `_sessions` 名字**保留**，因为它同时是测试的清空入口（`person_context._sessions.clear()`）与调试探针；类型从 dict 变成 store 对象，`clear()` 语义不变。

## 5. 明确没做到的部分

1. **不是真匿名化**。姓名、学位、签发日期仍然明文返回——这是产品语义（要能回答「他拿到什么学位」）。`hash_prefix` 与 `hashed_document` 也在返回里，它们是公开链 ID，可被拿去查完整凭证。真正的「按需披露」走 U4.4 的章节级披露，本批不改那条路径。
2. **`mask_student_id` 保留 4 位前缀**，8 位学号仍可暴力猜测（10^4 空间 + 姓名交叉）。保留前缀是为了让同时出现两个学生时人能分辨；要做强隐私应改为不可逆短哈希，但那会破坏「同一个学号在不同会话里看起来一致」的可用性。
3. **`NEVER_DISCLOSE` 只挡 key，不挡值**。有人把 DOB 塞进 `Honour` 字段照样会出去。值级检测需要 PII 分类器，本批不引入。
4. **会话没有过期**。只有 LRU 上限，没有 TTL——关了浏览器，服务端内存里还留着这个人的档案，直到被挤掉。多租户部署下这是真问题，已写进 `TODO[external-redis]` 的说明里。
5. **`_raw_documents()` 每次请求全量读** `rawjsondocs/`，没有缓存。会话多了会慢，但不影响正确性。
6. **Redis 后端不存在**。接口在两个实现之间的接缝是清楚的，但只有一个实现。
7. **前端未变**。删除的字段前端本来就没渲染，`person` 结构不变。
