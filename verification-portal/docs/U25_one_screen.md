# U25 — 一屏验证，三格签发

## 缺口

上一版把"简单"理解成了"功能齐全"：首页五个标签（开始 / 验证 / 学生 / AI 助手 /
日志）、四张角色卡、四格统计条。第一次来的人要先回答"你是谁"，系统才开始干活。
对一个只想确认"这张纸是不是真的"的 HR，这是三道前置题。

签发侧更糟：签发藏在 `/staff` 的第四个标签里，要登录、要选标签、要填十几格、
其中大部分字段（Sex、DegreeStartDate、DocType、IssuingO）一个办事员根本不该
关心。

## 改法

两个单用途页面，替代原来那个"什么都能干"的首页。

**`/` — 验证页。** 一句话标题（这张证书是真的吗？），一个输入框（粘贴验证码
**或** 选 PDF），一个按钮。回来后只有一句话：真的 / 已注销 / 查不到。六个检查
仍然在，折在「为什么？看六项检查」里，用中文短句写（链条没被改过、签发方可信、
链上有这张证书、文件跟编号对得上、数字签名有效、没有被注销），不再摆布尔值。

- 保留的能力：`?hash=` 深链（QR 就指向它）、三个样例 chip、公开报告下载、复制
  验证码、回执编号。
- 去掉的：角色卡、统计条、标签栏、批量、日志、AI 助手——它们都还在
  `/portal`，只是不再是第一屏。

**`/issue` — 签发页。** 三格：姓名、学号、学位 / 课程。补充信息（荣誉、签发
机构、签发日期）折叠起来，默认不出现。一个按钮。结果是三样东西：验证码、
凭证 PDF、**打开验证页看看**（`/verify?hash=…`，一次点击闭环）。

- 背后仍是 `POST /api/custom/build`，权限一点没放宽（`_admin_required`）。
- 页面先问 `/api/staff/whoami`：已有 staff 会话就不显示口令框；没有才展开，
  口令存 `sessionStorage`，不落盘。
- 接口 401 会把口令框打开并说明原因，而不是丢一个红叉。

**`/portal` — 旧首页原样保留。** 文件从 `static/index.html` 复制为
`static/portal.html`，内容未改；`main.js` 等资产照旧加载。没有删除任何路由。

## 教训

1. **"简单"是删掉第一屏，不是删掉功能。** 复杂能力全在 `/portal`，只是不再
   拦在门口。判断标准：一个陌生人从打开到拿到结论，需要几次决策？从五次降到
   一次。
2. **签发不是"高级功能"，是另一半产品。** 之前把它当 staff tab，导致演示时
   要先讲登录。给它独立页 + 三个字段之后，"另一个 portal 发证、这个 portal
   验"才成立。
3. **同一个动作别写两套接口。** `/issue` 直接复用 `/api/custom/build`，因此
   权限、校验、PDF 生成、文件落盘全部继承，没有产生第二条签发路径。
4. **口令框该藏就藏。** 先探测会话，再决定是否显示；默认不把 token 摆在一个
   公开页面上。
5. **深链比按钮更可靠。** `/verify?hash=` 一直是 QR 的落点，这次让它
   同时承担"签发完成 → 立刻看到结果"的跳转，比让用户自己复制粘贴强。
6. **改前端要重打包，也要提醒强刷。** 静态文件名没变，浏览器会拿旧缓存；给
   CSS/JS 加版本号或 `?v=` 是部署时唯一低成本的办法。

## 仍开着

- 静态资源没有指纹（无 hash 文件名 / 无 `Cache-Control: no-cache`），部署后
  老用户可能仍看到旧页。
- 验证页拿到 `VERDICT` 之外的异常（例如链条损坏）时只显示"无法确认"，没有把
  `chain_integrity=false` 单独放大成"这是系统问题，不是这张证书的问题"。
- 上传 PDF 时若自动提取失败，页面只报错，没有回退到"粘贴 JSON"的引导。
- `/issue` 没有签发历史列表（只在 `/portal` 和 `/api/custom/list` 里）。
- 三格表单没有客户端校验学号格式；服务端会收，等于把脏数据写进链。
