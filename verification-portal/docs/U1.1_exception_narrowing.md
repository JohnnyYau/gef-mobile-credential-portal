## 2. 异常 → HTTP 映射（现状，未改契约）

- `ValueError` / `ValidationError`（同时是 `ValueError` 子类）→ 路由层 `except ValueError` → **422**。
- `RuntimeError` / `PortalError` / `ChainDataError`（`RuntimeError` 子类）→ 路由层 `except RuntimeError` → **503**。
- 已用导入校验：`ValidationError` 同时是 `ValueError` 与 `RuntimeError` 子类；`ChainDataError` 是 `RuntimeError` 子类。

## 3. 验证结果

- 全量回归：**12/12 模块 PASS，108 用例全绿**（`scripts/run_all_tests.py`）。
- `ruff check app`：**4 errors**，均为 U0 既有 unsafe 项（`anomaly.py:71`、`anomaly.py:129`、`pdf_extractor.py:190`、`rag_indexer.py:231`），无新增。
- `mypy app`：**16 errors / 7 文件**，与 U0 末基线持平，无新增。
- `ruff check tests`：干净。

## 4. 本轮偏差与遗留

- 端点异常映射目前仍是各路由独立 `try/except`；集中式全局异常处理器（FastAPI exception handler）未落地，并入 U1.2/U1.3 服务层拆分时评估，避免本轮改动公开接口行为。
- `web_research.py` 两处外部网络兜底保持宽异常；待外部后端异常类型封闭后再收窄。
- 新增领域异常类型中，`SignerUnavailableError` / `UnavailableBackendError` / `FileAccessError` 已建模但尚未在服务层替换现有 `ValueError`/`RuntimeError` 抛出点；随 U1.2/U1.3 逐步迁移。
