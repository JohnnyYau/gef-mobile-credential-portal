### 2.1 Origin 守卫

放在**现有加固中间件的入口**，早于体积与限流判断：

```
有 Origin 头 + 非安全方法(GET/HEAD/OPTIONS) + 不在白名单 → 403
```

白名单来源两条：

1. `ALLOWED_ORIGINS` 环境变量（逗号分隔，为反向代理场景准备）；
2. `127.0.0.1` / `localhost` 恒允许（本机演示不该需要配置）。

**没有 `Origin` 头就放行**——curl、测试、服务端到服务端都不发这个头，缺它不构成攻击信号。这也是本步能零回归的前提：108 条测试全都不带 Origin。

**这条防护防的是什么**：浏览器跨站表单/脚本带上用户已有 Cookie 去触发 `POST /api/revoke`。本系统管理端点不用 Cookie 而是 `X-Admin-Token` 头，所以严格说 CSRF 面本来就窄；真正的价值是**挡住恶意页面驱动公开写端点**（如批量签发）。

### 2.2 PDF 魔数收紧（修正一个既有缺陷）

原实现两处都是：

```python
if raw.lstrip()[:4] != b"%PDF":
```

`lstrip()` **跳过所有前导空白与不可见字节**——意味着 `\x00\x01\x02...垃圾...%PDF` 这种文件能通过检查。实测确认：构造一段 50 组 `\x00\x01\x02garbage` 前缀的文件，旧逻辑放行、新逻辑 422。

新实现统一走 `_require_pdf_magic()`：在**前 1024 字节**内找 `%PDF`（PDF 规范允许头部出现在前 1024 字节内，部分生成器会先写 BOM 或注释）。两处调用点（`POST /api/extract/pdf`、`_parse_upload`）同时切换。

`_parse_upload` 的判定是"扩展名叫 .pdf **或** 内容像 PDF"，这里刻意保留"或"——用户把 `.pdf` 改成 `.json` 上传时，仍按 PDF 解析，与原契约一致。

## 4. 一个必须说清的设计选择

Origin 白名单我用的是 `ALLOWED_ORIGINS` 环境变量，**不是** CORS 中间件。

- 没上 `CORSMiddleware`：那个中间件是给"允许跨域**读取**响应"用的，它不拦写请求，且配错 `allow_origins=["*"] + allow_credentials` 会互相抵消；
- 这里做的是**拒绝**：只要 Origin 可疑就 403，比配 CORS 简单、也更容易说清行为。

代价：如果将来前端拆成独立域名，必须显式配置 `ALLOWED_ORIGINS`，否则写请求全 403。这条写进报告，避免以后被当成 bug。

## 5. 路径逃逸：为什么现在是"路由不匹配"而不是 403

`GET /api/pdf/{hashed_document}` 的路径参数里带 `../` 时，返回的是 **404**——因为 Starlette 的路由层已经把 `../` 当成路径分隔处理，根本没进到函数体。函数体里的 `_validate_hash()` 正则才是第二道防线（对超长、非法字符返回 422）。

两道防线都在，但**第一道在框架层**——这意味着如果以后有人把这条路由改成 `{path:path}` 通配（例如支持带斜杠的 ID），防护会瞬间失效。所以我把"改变路由参数类型"列为回归检查点写在这里。

---

## 6. 为什么没做私钥口令加密

计划里写的是"私钥口令加密 + `TODO[external-kms]` 占位"。没做，三个理由：

1. **私钥不在本服务里**：签名由链工具（`chain_core` 调用的外部 CLI）完成，私钥落在链工作目录，加密格式由那个工具决定。在这里加一层加密，要么与 CLI 的读取逻辑冲突直接签不了名，要么只是把同一把明文密钥换个地方放——两者都比现状更危险。
2. **做错了会锁死系统**：口令加密涉及"口令丢失即私钥丢失"。没有 KMS、没有恢复流程、没有轮换演练的前提下落地，是把一个可用的演示系统换成不可恢复的状态。
3. **`TODO[external-kms]` 是本项目红线**：既定 TODO 标注规则要求外部依赖入口留占位且不得改动既有 TODO。真要动手，得先确定是"接 KMS"还是"用口令 + 恢复码"，这是需要单独决策的设计题，不适合塞在加固步里顺带做。

**结论**：本步不动私钥存储，把这条留给 U8（部署与依赖批次），因为 U8 才涉及外部依赖与运行环境。这不是遗漏，是刻意不碰。
